Claude Code Harness ​

Inventaire de la configuration Claude Code du projet (dossier .claude/) qui pilote la modernisation : 11 agents, 12 skills (4 lanceurs, 6 conventions, 2 utilitaires), 7 rules auto-injectées, 8 commandes développeur, un hook PreToolUse et les permissions de settings.json. Les chemins de travail sont centralisés dans CLAUDE.md (section « Chemins »). Page régénérée par /mod-generate-docs harness, proposé par /dev:commit dès qu'un commit touche .claude/.

/mod-generate-docs [all|<feature>|<feature> status|harness]Génération / synchronisation de ce wiki VitePress, tableau de bord de l'équipe : modes complet, <feature>, <feature> status (léger : entrée du changelog seule, tableaux de bord, Cartographie et timeline étant calculés) et harness (cette page) ; chiffres calculés, jamais écrits à la main : data loader docs/.vitepress/data/migration.data.ts (source unique, expose aussi l'arbre fonctionnel ; contrôle de cohérence qui fait échouer le build) rendu par les composants MigrationDashboard / MigrationMetrics, par la timeline <MigrationTimeline feature="…" /> de chaque page feature (état, indicateurs, progression, liste des tâches API / Frontend calculés) et par la Cartographie <MigrationMap /> (graphe de dépendances, vagues de migration, arbre fonctionnel déplié en profondeur au clic ; filtres, sélection avec chaîne de dépendances, panneau de détail, vue partageable par URL ; ECharts 5.5.0 en dépendance npm du wiki) ; copies canoniques dans references/wiki-src/ (data loader, 4 composants Dashboard / Metrics / Map / Timeline, index.ts, custom.css, pages/mapping-index.md), resynchronisées à chaque mise à jour ; règles migration-status.md (3 barres nommées, couleurs d'état dont spec non disponible en gris, barre par feature toujours verte, titres ### BACKEND- et Statut acceptés) ; mise en page (zone centrale élargie, titre court + sous-titre « Modernisation ») ; table des déclencheurs portés par les launchers— (exécution directe)

Permissions (settings.json) ​

Préfixe docker compose exec -T app php abrégé en … ; bin/console limité à une liste blanche de sous-commandes (les autres demandent confirmation).

43allow
… bin/phpunit *, … bin/console about *, cache:clear, cache:warmup, debug:router, debug:container, debug:autowiring, debug:config, debug:event-dispatcher, router:match, lint:container, lint:yaml, make:entity, make:migration, make:fixtures, doctrine:database:create, doctrine:migrations:diff, doctrine:migrations:migrate, doctrine:migrations:status, doctrine:migrations:generate, doctrine:schema:validate, doctrine:mapping:info, docker compose ps *, … vendor/bin/phpcs *, … vendor/bin/phpcbf *, git add *, mkdir *, jq empty *, npm run lint *, npm run typecheck *, npm run format *, npm run format:check *, npm run test *, npm run test:unit *, npm run test:integration *, npm run test:coverage *, npm run build *, npm test *, npm ci *, npm run docs:build *, docker compose up -d *, Edit(/output/**), Edit(/classified-ads-wiki/**)
8ask
git commit *, git push *, … bin/console doctrine:database:drop *, doctrine:schema:drop, doctrine:fixtures:load, doctrine:query:sql, dbal:run-sql, doctrine:schema:update
4deny
Edit(/php-legacy/**), Edit(.env*), Read(.env*), Bash(rm -rf *)

Hook PreToolUse (Bash) : .claude/hooks/block-rm.sh refuse les suppressions récursives (rm -r, git rm -r sans --cached, find -delete, y compris derrière un lanceur ou dans une substitution) ; requiert jq. Variable d'environnement CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR=1 : chaque commande Bash repart de la racine du projet.
