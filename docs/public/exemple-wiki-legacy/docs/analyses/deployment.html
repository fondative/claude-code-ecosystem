05 - Déploiement et environnements ​

1. Environnements ​

EnvironnementExistenceMécanismeConstat
Développement localOuiDocker Compose (docker-compose.yml)Seul environnement outillé
Staging / recetteNon—Aucune configuration dédiée
ProductionImpliciteInstallation manuelle décrite dans le README (upload FTP + import SQL + édition de config.php)Pas de pipeline, pas de procédure de mise à jour du schéma

Il n'existe aucune notion d'environnement dans le code (pas de variable APP_ENV, pas de mode debug configurable) : display_errors est forcé à 0 dans les deux fichiers de configuration (config.php:5, config.docker.php:5), tandis que des appels debug() restent actifs en production (ad-placement.php:225,229, user-registration.php:112).

2. Architecture de déploiement (Docker) ​

2.1 Image applicative (Dockerfile) ​

ÉtapeLigneDétail
Image de base1php:5.6-apache
Sources APT3-4Bascule sur archive.debian.org (Stretch) avec [trusted=yes]
Extensions8-16gd (JPEG/FreeType), mysqli, mysql, pdo, pdo_mysql
Apache19a2enmod rewrite (aucune règle de réécriture n'est fournie)
Code25COPY . /var/www/html/ (le .dockerignore exclut .env, .git, docs/, *.md)
Uploads28-30mkdir upload ; chown -R www-data ; chmod -R 755 sur tout le docroot
Exposition33Port 80

Points d'attention :

  • Le répertoire upload/ est dans le docroot et n'est pas un volume : les images déposées sont perdues à la recréation du conteneur.
  • Le code est copié dans l'image (pas de bind mount du code) : toute modification nécessite un rebuild.
  • Aucun php.ini de production (limites d'upload, session.cookie_httponly, expose_php...) hormis docker/mailpit.ini.
  • Pas de healthcheck ; depends_on ne garantit pas que MySQL soit prêt au démarrage de web.

2.2 Volumes montés ​

Aucun volume nommé pour les données MySQL : les données vivent dans le conteneur db (perdues à sa suppression).

Le fichier .env à la racine de php-legacy/ est présent et versionné dans Git (git ls-files le liste), alors qu'il contient des identifiants de base de données. Son contenu n'est pas reproduit ici.

D'autres constantes sont dispersées dans le code : 15 annonces par page (ad-list.php:92), 10 en admin (admin/ad-list.php:37), 512 000 octets max par image (picture-upload.php:20), miniatures 150x150 (thumb.php:34-35), longueurs de description 500 / message 200-500.

4. Processus de déploiement actuel ​

4.1 Installation « classique » (README) ​

Aucune étape n'est automatisée : pas de CI/CD, pas de versionnement de schéma, pas de script de mise à jour, pas de tests de non-régression.

4.2 Points de vigilance opérationnels ​

SujetConstat
Compte administrateurCréé par db-install.sql:228-229 avec un mot de passe par défaut faible, en clair, sans obligation de changement
Permissions fichiersupload/ doit être inscriptible par Apache ; mkdir(..., 0777, true) à chaque date (picture-upload.php:61,70)
Exécution de PHP dans upload/Aucune règle Apache n'empêche l'exécution de scripts dans le répertoire d'upload (voir 06-audit.md)
Tâches planifiéesAucune (expiration des annonces, notifications expirednotice non implémentées)
LogsLogs Apache par défaut uniquement ; aucune journalisation applicative
SauvegardeNon prévue (ni BD ni images)
HTTPSNon géré (URLs construites en http://, ad-placement.php:120)

5. Setup de développement local ​

5.1 Prérequis ​

  • Docker et Docker Compose
  • Ports libres : 8080, 8081, 3306, 8025, 1025

5.2 Démarrage ​

bash
cd php-legacy
# le fichier .env doit définir DB_NAME, DB_USER, DB_PASSWORD, DB_ROOT_PASSWORD,
# SITE_URL, ADMIN_EMAIL, NOREPLY_EMAIL
docker compose build
docker compose up -d

5.3 Accès ​

ServiceURL
Applicationhttp://localhost:8080
Back-officehttp://localhost:8080/admin/
phpMyAdminhttp://localhost:8081
Mailpit (emails capturés)http://localhost:8025

5.4 Réinitialisation de la base ​

Les scripts docker-entrypoint-initdb.d ne sont rejoués que sur un datadir vide :

bash
docker compose down        # supprime les conteneurs (et les données MySQL, faute de volume nommé)
docker compose up -d --build

5.5 Débogage ​

  • display_errors est à 0 : consulter docker compose logs web pour les erreurs PHP.
  • La fonction debug($var) (common.php:227) affiche un print_r dans la page.
  • Les emails envoyés sont consultables dans Mailpit (l'activation d'une annonce nécessite le lien reçu par email).
