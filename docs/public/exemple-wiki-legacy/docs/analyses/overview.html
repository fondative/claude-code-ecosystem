01 - Vue d'ensemble de l'architecture ​

Projet analysé : php-legacy/ — « Legacy Classified Ads Script » (petites annonces), v1.0.2, licence GPL v3, auteur Szilard Szabo. Code d'origine daté de 2004-2012 (dump SQL généré le 20/02/2012, PHP 5.3.5 / MySQL 5.5.8), dockerisé ultérieurement (commit 302edc3 dockerise app).

2. Architecture de haut niveau ​

Cycle d'une requête ​

Chaque script public suit le même schéma « Page Controller » :

  1. include("./admin/include/common.php") : charge la configuration, ouvre la connexion MySQL, charge toutes les classes modèles et exécute systématiquement plusieurs requêtes globales (arbres catégories/régions, compteurs, menu admin via SHOW TABLES) — admin/include/common.php:18-67.
  2. Lecture et nettoyage des paramètres $_GET / $_POST (via (int) ou strip_tags).
  3. Appel aux méthodes statiques des modèles (Ad::get_all, User::login, ...).
  4. include("./templates/<page>.php") : le template accède directement aux variables globales du script.

Côté administration, la logique et le HTML sont dans le même fichier (pas de séparation template).

6. Caractéristiques notables ​

  • Pas de séparation des couches : la validation métier, l'accès BD, l'envoi d'email et le rendu sont mélangés dans les page controllers (ex. ad-placement.php, 240 lignes).
  • Rôle administrateur codé en dur : l'admin est l'utilisateur id = 1 (admin/*.php:15, user-ban.php:12). Aucun modèle de rôles.
  • Balises courtes <? / <?= dans 49 fichiers (templates, db.php) : dépendance à short_open_tag = On.
  • Code et commentaires partiellement hongrois : colonne ar (« prix ») dans ad-list.php:85, index nev, bejnev, jelszo, aktiv dans db-install.sql, messages « Nem muxik ... » dans thumb.php:43.
  • Copie dupliquée de la librairie Pager (/Pager et /admin/Pager, contenu identique).
