06 - Audit de qualité et recommandations ​

Périmètre : php-legacy/ (137 fichiers PHP, ~10 700 lignes hors PEAR Pager). Analyse statique manuelle, sans exécution de tests d'intrusion. Échelle : CRITIQUE > ÉLEVÉE > MOYENNE > BASSE.

Synthèse ​

CatégorieCRITIQUEÉLEVÉEMOYENNEBASSE
Sécurité5862
Performance0142
Qualité du code0343
Scalabilité0231
Maintenabilité1331

Le constat principal : l'application cumule des vulnérabilités exploitables sans authentification (injection SQL, upload de fichier exécutable, XSS) sur une pile logicielle (PHP 5.6, MySQL 5.5) qui ne reçoit plus de correctifs. Ces points justifient la migration prévue et, d'ici là, une non-exposition de l'application sur Internet.

Gaps identifiés ​

  • Aucune vérification des règles métier (cycle de vie annonce, unicité des avis, bannissement, expiration).
  • Aucun test de sécurité (injection, XSS, upload).
  • Le code legacy est difficilement testable unitairement (méthodes statiques, globales, mail() et eval() directs).

Logging et monitoring ​

Aucun : pas de journal applicatif, pas de traçabilité des actions admin (suppression, bannissement), pas de métriques, pas d'alerting, pas de healthcheck Docker.

Améliorations recommandées (cible) ​

  • Exceptions métier typées + gestionnaire global renvoyant des erreurs API normalisées (RFC 7807 / Problem Details).
  • Validation déclarative (Symfony Validator / schémas côté React) centralisée, messages traduisibles.
  • Journalisation structurée (Monolog, niveau par environnement) avec journal d'audit des actions d'administration.
  • Envoi d'emails via Symfony Mailer + Messenger (retry, dead letter).
  • Healthchecks Docker et endpoint de santé ; supervision des erreurs (ex. Sentry).
