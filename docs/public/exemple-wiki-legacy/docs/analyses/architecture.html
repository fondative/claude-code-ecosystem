Architecture : legacy et cible ​

Cette page met en regard l'architecture du legacy (rétro-ingénierie : Vue d'ensemble, Flux et logique, Déploiement) et l'architecture cible de la modernisation (Symfony 7.4 API REST + React 19 + PostgreSQL, sous Docker Compose).

Statut de la cible

Les projets cibles (api-rest-symfony-target/, app-react-target/) ne sont pas encore créés. Les diagrammes « cible » décrivent l'architecture prévue par les conventions du projet (skills sym-api-conventions et front-app-conventions), pas un code existant.

1. Architecture legacy ​

Monolithe PHP procédural rendu côté serveur : 25 scripts publics et 37 scripts d'administration jouent le rôle de page controllers, partagent un bootstrap commun (common.php) et une couche d'accès aux données statique (Table / TreeTable), puis incluent des templates PHP qui lisent des variables globales.

2. Architecture cible ​

Séparation stricte entre une API REST JSON (Symfony 7.4 / PHP 8.2, documentée en OpenAPI) et une SPA React 19. Chaque requête suit la chaîne Controller → DTO validé → Service → Repository Doctrine → Mapper.
